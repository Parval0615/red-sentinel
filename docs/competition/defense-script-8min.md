# RedSentinel 8 分钟答辩/讲解稿

## 开场：40 秒

各位老师好，我们的项目叫 RedSentinel，中文名“灵哨”，面向的是“面向大模型及应用的安全性研究”方向。

一句话概括：我们从红队视角研究 LLM Agent 的攻击面，并做了一套旁路行为监督机制，能够记录模型响应、工具调用、guard decision 和审计引用，再用评测与防御 Agent 形成可复现的攻防闭环。

最终离线结果是：Adaptive Defense ASR 从 44% 经过 7 轮加固下降到 0%；去掉 Defense Agent 后该指标仍保持 44%；去掉 Attack reflection 后攻击面覆盖只能停在 2/7，而完整系统可以覆盖 7/7。

## 问题背景：60 秒

现在的 LLM Agent 不只是聊天，它会检索知识库、调用工具、读写记忆，甚至执行订单、退款、改价这类业务动作。能力越强，攻击面越复杂。

在电商场景里，提示注入可能让客服越权退款；知识库投毒可能让导购推荐假货或竞品；工具篡改可能造成恶意改价；越权检索可能泄露他人的订单和地址；目标漂移可能让 Agent 偏离用户真实需求。

传统安全测试往往靠人工红队和固定规则，覆盖面有限，也很难证明防御是否持续有效。我们的目标是把“攻击面研究、行为监督、风险量化、防御回归”放进一条可离线复现的链路。

## 系统方案：90 秒

RedSentinel 由三个智能体、一个本地靶场和一层旁路监督机制组成。

第一个是 Attack Agent。它负责从红队视角生成攻击计划、越狱载荷和对抗样本。如果攻击失败，它会进行 reflection，沿策略阶梯升级，生成下一轮攻击变体。

第二个是旁路监督层。它不是只看最终回答，而是记录响应、工具调用、guard decision、risk level、attribution 和 audit refs。这样每个风险事件都能回到具体轨迹。

第三个是 Evaluation / Defense Agent。Evaluation Agent 量化 ASR、覆盖率和误伤率；Defense Agent 根据损伤报告选择 prompt、rule、retrieval、rerank 等精准加固动作。

靶场是本地电商 RAG Agent，覆盖搜索、导购、订单、支付模拟、退款、客服和商家运营。所有数据都是本地合成数据，不接真实淘宝、不接真实支付、不接真实用户数据。

## 能力实现：150 秒

第一项能力是攻防监督闭环。单条命令 `python run.py --demo` 可以离线串起攻击、靶场、监督、评测、防御和审计，生成 trace、report、guard decisions、audit refs 和 summary。

第二项能力是红队攻击战役。命令是 `python run.py --comp2 --offline`。Attack Agent 会在 7 类威胁分类上进行攻击规划，失败后反思并升级策略。离线结果显示，加入 reflection 后攻击面覆盖可以达到 7/7。

第三项能力是防御策略回归。命令是 `python run.py --comp3 --offline`。系统先跑基线攻击得到损伤报告，再让 Defense Agent 对每个被攻破类别选择精准加固动作，然后重打同一攻击战役，并用良性请求测试误伤。结果是 Adaptive Defense ASR 从 44% 降到 0%，精准加固误伤率 0%。

第四项能力是风险证据包。命令是 `python run.py --comp4 --offline`。它生成多轮 ASR 收敛曲线、加固前后损伤雷达图、三组消融实验和 AgentRiskBench-Ecommerce 数据卡。

## 实验结果：100 秒

我们重点看三个实验结论。

第一，红队攻击面可以系统覆盖。去掉攻击反思时只能覆盖 2/7；完整攻击战役可以覆盖 7/7，说明 reflection 能扩大风险发现范围。

第二，对抗是收敛的。Adaptive Defense 初始 ASR 是 44%，系统每轮针对一个被攻破威胁类别加固，经过 7 轮后 ASR 下降到 0%。

第三，防御不是简单全拦。精准加固误伤率是 0%，而一刀切防御误伤率是 100%。这说明旁路监督和按威胁类别选择的策略比粗暴阻断更适合真实 Agent 应用。

## 创新总结：60 秒

我们认为项目创新主要有四点。

第一，把 LLM 应用安全从单条样本测试扩展为红队攻击面战役。

第二，把旁路监督信号纳入闭环，能够记录工具调用、风险决策、归因和审计引用。

第三，用 ASR 作为统一指标，把攻防是否有效变成可观察的收敛曲线。

第四，所有核心结果都支持离线确定性复现。无 API key 时，评委仍然可以用 `--offline` 跑出同样结论。

## 边界与收尾：20 秒

最后说明边界：项目只作用于本地合成电商靶场，不连接真实淘宝、真实支付、真实用户数据或外部攻击目标。
